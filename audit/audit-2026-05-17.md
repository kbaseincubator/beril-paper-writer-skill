## 2. Bash flow — retire or retain?

### Files

| File | LOC | Purpose |
|---|---|---|
| `src/beril_paper_writer/skill/tools/paper_writer.sh` | 3,468 | Top-level bash orchestrator (draft / resume subcommands) |
| `src/beril_paper_writer/skill/tools/paper_writer_helpers.py` | 4,679 | Python helper CLI invoked by paper_writer.sh; ~25 subcommands |

### What the Python orchestrator actually calls from helpers

Grep of `orchestrator.py` for `paper_writer_helpers`: **0 matches.** The Python orchestrator never calls paper_writer_helpers.py directly.

Cross-references in other Python modules are mostly comment-level (the modules note paper_writer.sh's existence in docstrings but don't invoke it).

The one helper subcommand the Python orchestrator DOES need is `extract-tier` — but Stage 3 Tier D inlined this logic by calling `paper_writer_helpers._extract_tier_from_text` *as a Python import*, not as a subprocess. So even `extract-tier` is reachable without invoking the helper CLI.

### What paper_writer.sh does that the Python orchestrator doesn't

From grepping the script:

- Parallel best-of-3 fallback reviewer (`run_fallback_reviewer ... & & & wait`) — Adam's $53.70 cost overrun came from this; the Python orchestrator runs the fallback once, not parallel
- Glyph cross-walk check post-plan (`check_throughline_glyphs.py`)
- handoff JSON writing via `paper_writer_helpers.py write-handoff`
- state.json mutation via `paper_writer_helpers.py update-state`
- Per-call metadata.json sidecars (older cost-tracking, superseded by Stage 1 Tier D's helper)
- `aggregate-metadata` at end to produce `run_metadata.json` (superseded by `state.cost_so_far_usd`)
- Reframing log init
- A handful of run-control utilities (init-reframing-log, fill-template, validate-handoff)

Some of this is redundant with the Python orchestrator (cost tracking, handoff). Some still has value (glyph cross-walk; reframing log init) but should live in Python.

### Recommended action — RETIRE BASH FLOW

1. Audit paper_writer_helpers.py subcommands; identify the 2–4 that still produce value (e.g., glyph cross-walk, reframing log init) and port their *logic* into Python helpers callable from the orchestrator.
2. Delete `paper_writer.sh`.
3. Delete `paper_writer_helpers.py` (or strip it to only the Python-importable functions like `_extract_tier_from_text` and a few utilities).
4. Audit `draft.py`'s docstring — it still says "Thin Python wrapper around `tools/paper_writer.sh draft`." That's wrong and explains some of the install-state confusion earlier. Update.
5. Audit `assemble.py`'s `_locate_paper_writer_sh` mirror — delete the dead function.
6. Verify no test exercises the bash flow (would need updating).

This is the biggest cleanup; estimate ~half a day to do carefully. Wait for Tier-K's live verification before pulling the trigger — the current bash flow is still reachable as a safety net.
