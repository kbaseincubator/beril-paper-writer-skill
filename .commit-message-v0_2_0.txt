v0.2.0 — discipline-hardening + auto-repair tier

Three architectural tiers landed since v0.1.0 (88eac762):

Tier 1 — Cross-walk post-processors (advisory; $0 smoke)
========================================================
- tools/check_scope_coherence.py — Discussion ↔ Results scope cross-walk
  + would-NOT-include bullet match. Literature-attribution skip,
  distinctive-keyword filtering, top-8 keyword 3-hit threshold.
- tools/check_overclaim.py — Abstract/Discussion strong-verb vs
  ⚠ partial / ✗ contradicts evidence-map cross-walk. ≥2-distinctive
  overlap gate eliminates cross-claim FPs. Marks
  [caveat-acknowledged] when sentence inline contains caveat
  vocabulary or numerical anchors.
- Wired in paper_writer.sh between phase_finalize_citations and
  phase_assemble. Smoke against draft_1: 4+4=8 advisory WARNs, all
  real-signal except 1 documented borderline FP.

Tier 3 — REPAIR_MODE harness + review-rewrite loop ($6.36 live retest)
======================================================================
- phase_repair_validators in paper_writer.sh — reads
  audit/validation.json, dispatches each failed M2-M10 validator to
  the section prompt that owns repairs per LAYOUT.md:419 dispatch
  table, in REPAIR_MODE with 4 documented inputs. Bounded retry
  (2 dispatches/validator). M1 / M4 escalate per LAYOUT, not
  REPAIR_MODE. M10 has location-based tie-breaker.
- phase_review_rewrite — parses latest review.md for
  Critical+Important (pass 1) or Critical-only (pass 2) findings,
  dispatches rewrite.v1.md per primary section with FINDING_IDS
  JSON array, re-assembles + re-validates after each pass, runs
  reviewer pass 2 (and 3 if needed). SPEC §8.3 hard cap of 2
  rewrite passes enforced.
- tools/check_repair_scope.py — fourth post-processor in the pattern.
  Three checks per repair attempt: pre/post byte-identical
  (Write no-op), bounded diff via difflib (≥30% WARN, ≥60% strong),
  validator regression (any pre.pass → post.fail).
- 5 new helper subcommands: prepare-repair, check-repair-status,
  list-failed-validators, parse-review, count-review-criticals.
- emit-next-actions extended with REPAIR_MODE outcomes + Review-
  rewrite outcomes sections, escalations / repaired / loop-trace
  prioritized.

Tier 5 — Defensive features ($0 smoke)
======================================
- paper_writer_helpers.py extract-data-availability — replaces v0.1's
  [TBD] markers in 07_data_availability.md with real values. K-BERDL
  databases extracted from methods_provenance.md SQL via regex on
  FROM <db>.<table> patterns (deterministic). Public accessions via
  curated pattern set (Fitness Browser, GTDB, NMDC, AlphaEarth,
  GapMind, eggNOG, Bakta, STRING, PubMed, PaperBLAST) + typed
  accessions (BioProject, GEO, SRA, GenBank, DOI, PMID — normalized
  to strip type-prefix). Falls back to [TBD] if extraction empty.
  Smoke on functional_dark_matter: 3 K-BERDL databases + 9 named
  sources + 17 PMIDs.
- --max-cost-usd N CLI flag — cost circuit breaker.
  invoke_claude_with_retry checks cumulative audit/*.metadata.json
  estimated_cost_usd before each LLM call; halts via halt_with if
  cap exceeded. New helper: paper_writer_helpers.py cumulative-cost.

Bug fix — review-finding parser tolerance
=========================================
fallback_reviewer.v1 emits ≥3 finding-header shapes:
  Form A: **C1: Abstract line 18 — "..."**
  Form B: - **C1: Abstract functional hypotheses claim (line 20)** — "..."
  Form C: - **C3: "Multi-dimensional ..." (Abstract line 18, ...)** — ...
v0.2 retest exposed Forms B+C; parser silently returned 0/3 Criticals
on review_2.md and terminated rewrite loop one cycle early. Fix:
full-header-line matching + section-name scan over header + next 6
body lines (header-first, body-fallback). Tested against both shipped
review files; no regression on Form A; 3/3 on Forms B+C.
